# 网络安全入门

## 概述

### 1、什么是网络安全？

**网络安全**是指保护网络系统中的硬件、软件及数据，使其不被破坏、更改或泄露，并保障系统能持续、可靠地正常运行。核心目标通常概括为 **CIA 三元组**：

| 目标 | 英文 | 含义 |
| --- | --- | --- |
| **机密性** | Confidentiality | 数据只能被授权方访问 |
| **完整性** | Integrity | 数据未被篡改或损坏 |
| **可用性** | Availability | 服务在需要时可用 |

在 CIA 之外，实务中还会强调：

| 扩展目标 | 含义 |
| --- | --- |
| **认证（Authentication）** | 确认「你是谁」 |
| **授权（Authorization）** | 确认「你能做什么」 |
| **不可否认（Non-repudiation）** | 操作可追溯、难以抵赖 |
| **审计（Audit）** | 关键行为可记录、可排查 |

### 2、攻击面大致分几层？

| 层级 | 典型问题 | 例子 |
| --- | --- | --- |
| **网络层** | 窃听、伪造、拒绝服务 | MITM、DDoS、DNS 劫持 |
| **传输/会话层** | 明文、会话被盗 | 无 HTTPS、Cookie 被窃 |
| **应用层** | 注入、越权、逻辑漏洞 | XSS、SQL 注入、CSRF |
| **数据与密钥** | 泄露、弱加密 | 密钥进仓库、弱哈希 |
| **人与流程** | 钓鱼、误配、供应链 | 钓鱼邮件、依赖投毒 |

> 多数 Web 业务事故出在**应用层 + 配置 + 人**，而不是「防火墙没开」。

### 3、和 OWASP Top 10 的关系

业界常参考 [OWASP Top 10](https://owasp.org/www-project-top-ten/) 做排查清单。下面各小节覆盖其中大部分常见项（注入、失效的访问控制、加密失败、设计缺陷、错误配置、组件漏洞、认证失败、软件与数据完整性失败、日志不足、SSRF 等）。

## 常见的网络安全问题

### 1、XSS（跨站脚本攻击）

攻击者把恶意脚本注入到网页中，其他用户浏览时脚本在浏览器中执行，可窃取 Cookie、伪造请求、篡改页面、钓鱼输入框等。

| 类型 | 说明 | 典型场景 |
| --- | --- | --- |
| **反射型** | 恶意脚本经 URL / 表单「反射」进页面，一般不落库 | 搜索页回显关键词 |
| **存储型** | 脚本写入数据库，访问时自动执行 | 评论、昵称、公告 |
| **DOM 型** | 前端用不可信数据操作 DOM，脚本在客户端执行 | `location.hash` 写入 `innerHTML` |

危险写法示意：

```js
// 危险：把 URL 参数直接塞进 HTML
const q = new URLSearchParams(location.search).get('q')
document.getElementById('result').innerHTML = q
// 访问 ?q=<img src=x onerror=alert(1)> 即可触发
```

相对安全的做法：

```js
// 优先用 textContent；必须插 HTML 时做严格消毒
el.textContent = q
// 或使用成熟消毒库（如 DOMPurify）后再赋值
```

**常见防护：**

- 输出编码 / 按上下文转义（HTML、属性、JS、URL 规则不同）
- Cookie 设 `HttpOnly`（JS 读不到会话 Cookie）
- 开启 **CSP**（Content-Security-Policy）限制脚本来源
- 避免 `innerHTML` / `eval` / `document.write` 拼接不可信内容
- 对富文本用白名单消毒，而不是简单黑名单过滤

### 2、CSRF（跨站请求伪造）

用户已登录可信站点 A，攻击者诱使其在站点 B（或恶意页面）发起对 A 的请求。浏览器会**自动带上** A 的 Cookie，从而在用户不知情时完成转账、改密、发帖等操作。

典型攻击链：

```text
用户登录 bank.com → Cookie 仍有效
  → 打开 evil.com
  → evil.com 触发 <img src="https://bank.com/transfer?to=hacker&amount=1000">
  → 浏览器自动带上 bank.com 的 Cookie → 转账成功
```

**常见防护：**

| 手段 | 说明 |
| --- | --- |
| **CSRF Token** | 表单/请求头带随机 Token，服务端校验 |
| **SameSite Cookie** | `SameSite=Lax` 或 `Strict`，跨站请求不带 Cookie |
| **自定义请求头** | 如 `X-Requested-With`，跨域需预检，简单伪造更难 |
| **二次确认** | 改密、支付等要求再次输入密码 / 验证码 |
| **关键方法** | 状态变更用 POST/PUT/DELETE，勿用 GET 做写操作 |

> XSS 能偷 Token 时，CSRF 防护可能失效——二者常需一起防。

### 3、SQL 注入

把用户输入拼进 SQL，使语句语义被改变，可能造成越权查询、删库、拖库、读文件等。

```sql
-- 危险示例：直接拼接
SELECT * FROM users WHERE name = '" + userInput + "';
-- 若 userInput = ' OR 1=1 --  则可能查出全部用户
```

安全写法（参数化 / 预编译）：

```js
// 伪代码：占位符绑定，输入不会变成 SQL 语法
db.query('SELECT * FROM users WHERE name = ?', [userInput])
```

变种还包括：**NoSQL 注入**（如 MongoDB 操作符注入）、**ORM 误用**（仍拼接字符串）、**二阶注入**（入库时看似安全、后续拼接时触发）。

**常见防护：** 参数化查询 / 预编译、慎用动态表名列名（必须用白名单）、数据库账号最小权限、关闭详细 SQL 报错回显、WAF 作为纵深补充（不能当唯一手段）。

### 4、命令注入 / 代码注入

应用把用户输入拼进系统命令或动态代码中执行，危害往往比 SQL 注入更大（可直接控机）。

```js
// 危险：拼接 shell
exec(`ping ${userHost}`)
// 输入 127.0.0.1; rm -rf /  可能造成灾难
```

**常见防护：** 避免调用 shell；必须时用参数数组 API、严格白名单；禁用危险函数；容器与系统权限最小化。

### 5、中间人攻击（MITM）

攻击者夹在通信双方之间，窃听或篡改流量，常见于公共 Wi-Fi、伪造热点、恶意代理、证书被替换等场景。

**常见防护：** 全程 HTTPS/TLS、严格校验证书（勿在生产忽略证书错误）、开启 **HSTS**、移动端可做证书固定（Pinning）、内网管理接口也不要明文。

### 6、DDoS（分布式拒绝服务）

大量伪造或真实请求淹没目标，使服务不可用。

| 类型 | 特点 | 例子 |
| --- | --- | --- |
| **流量型** | 带宽被打满 | UDP Flood、放大攻击 |
| **协议型** | 耗尽连接/状态资源 | SYN Flood |
| **应用层** | 打满业务接口 CPU/DB | HTTP Flood、慢速攻击 |

**常见防护：** CDN / 高防、限流与熔断、WAF、弹性扩容、验证码/挑战、黑洞与流量清洗。业务侧可对昂贵接口（搜索、导出、登录）单独限流。

### 7、弱口令与撞库 / 暴力破解

密码过弱、多站复用，或攻击者用泄露的账号密码库批量尝试登录（**凭证填充 Credential Stuffing**）。

**常见防护：**

- 强密码策略 + 泄露密码库检测（如 Have I Been Pwned 类接口）
- **多因素认证（MFA）**
- 登录限流、验证码、异常登录告警
- 密码**加盐哈希**存储（`bcrypt` / `scrypt` / `Argon2`），禁止明文或可逆加密当「存储」
- 会话失效、改密后踢下线

### 8、敏感信息泄露

接口、日志、错误页、前端包、`.env`、Git 历史、Swagger 未鉴权文档中暴露密钥、Token、内网地址、身份证号等。

常见泄漏源：

| 来源 | 例子 |
| --- | --- |
| 前端 | 打包进 JS 的 API Key、调试开关 |
| 接口 | 多余字段（手机号、内部 id） |
| 报错 | 堆栈、SQL、绝对路径 |
| 仓库 | 提交过的密钥即使后来删了仍在历史里 |

**常见防护：** 密钥进环境变量 / KMS、接口字段白名单与脱敏、生产关闭详细报错、仓库密钥扫描、日志脱敏、定期轮换凭证。

### 9、未授权访问与越权（IDOR）

| 类型 | 含义 | 例子 |
| --- | --- | --- |
| **未授权** | 未登录也能访问 | 管理接口漏鉴权 |
| **水平越权** | 同角色访问他人资源 | 改 `orderId` 看别人订单 |
| **垂直越权** | 低权限调高权限接口 | 普通用户调删除用户 API |

```http
GET /api/orders/1001   ← 登录用户 A
GET /api/orders/1002   ← 若仍能返回，可能是水平越权（IDOR）
```

**常见防护：** 每个接口服务端鉴权；**每次**按「当前用户 + 资源」校验归属；统一鉴权中间件；勿只靠前端隐藏按钮；管理接口独立鉴权与网络隔离。

### 10、不安全的文件上传

上传可执行脚本、木马、双后缀、超大文件或图片马，导致服务器被控、XSS（SVG/HTML）或磁盘打满。

**常见防护：**

- 后缀 / MIME **白名单**（不要只信客户端）
- 服务端重命名、随机文件名
- 存对象存储，Web 目录禁止执行脚本
- 限制大小；图片可重解码再存
- 病毒扫描（视业务需要）

### 11、点击劫持（Clickjacking）

把目标站点嵌在透明 iframe 中，诱导用户点击看似无关的按钮，实际触发目标站点操作（关注、授权、转账确认等）。

**常见防护：** 响应头 `X-Frame-Options: DENY`（或 `SAMEORIGIN`），或 CSP：`frame-ancestors 'none'`；关键操作二次确认。

### 12、开放重定向（Open Redirect）

登录、分享链接等把 `redirect` 参数指到任意外域，用于钓鱼：用户以为还在可信站，实际被带到仿冒站。

```text
https://trusted.com/login?next=https://evil.com/fake-login
```

**常见防护：** 重定向目标白名单；只允许相对路径；禁止任意外链跳转或二次确认。

### 13、SSRF（服务端请求伪造）

服务端根据用户提供的 URL 去发起请求，被利用访问内网、云元数据、本地服务。

```text
用户提交 imageUrl = http://127.0.0.1:6379/
或 http://169.254.169.254/（云厂商元数据）
→ 服务器代为请求 → 内网信息泄露 / 进一步攻击
```

**常见防护：** URL 白名单、禁止内网 IP 与特殊协议（`file://`）、DNS 重绑定防护、出网隔离、禁用跟随危险重定向。

### 14、XXE（XML 外部实体注入）

解析 XML 时若允许外部实体，可读本地文件、造成 SSRF 或拒绝服务。常见于老旧 XML 解析器、SOAP、部分文档导入功能。

**常见防护：** 禁用外部实体与 DTD；能不用 XML 就用 JSON；升级解析库。

### 15、CORS 配置不当

为了「方便联调」把 `Access-Control-Allow-Origin` 设为 `*`，或**反射任意 Origin**，再配合 `Access-Control-Allow-Credentials: true`，可能导致跨站读到敏感接口数据。

**常见防护：** 精确白名单 Origin；带 Cookie 的接口绝不 `*`；按接口区分公开/私有 CORS 策略。

### 16、JWT / Session 使用不当

| 问题 | 说明 |
| --- | --- |
| 算法可切换 | 接受 `alg: none` 或弱算法 |
| 密钥过弱 | 可被爆破伪造 Token |
| 未校验过期 / 签发方 | 过期 Token 仍可用 |
| 敏感信息放 Payload | JWT 默认只签名不加密，可被解码阅读 |
| Session 固定 | 登录前后 Session ID 不变，可被固定攻击 |

**常见防护：** 强随机密钥、明确算法白名单、校验 `exp`/`iss`/`aud`、短过期 + Refresh、敏感数据勿塞明文 JWT、登录成功后轮换 Session ID、提供注销与黑名单（视方案）。

### 17、钓鱼与社会工程

伪造邮件、短信、客服、网站骗取账号、验证码或诱导安装木马。技术防线之外，**人**常是最薄弱一环。

**常见防护：** 安全意识培训、核验域名与证书、官方渠道二次确认、邮件防钓鱼网关、高危操作二次验证。

### 18、供应链与依赖风险

第三方库、CDN、CI/CD、npm/pip 包被投毒或存在已知 CVE，一次 `npm install` 可能引入后门。

**常见防护：** lockfile 锁定版本、依赖漏洞扫描（npm audit、Snyk 等）、CDN 资源加 **SRI**、最小第三方、CI 凭证最小权限、维护 SBOM、关注官方安全公告并及时升级。

### 19、安全配置错误

默认口令、目录列表开启、调试模式上生产、云存储桶（Bucket）公共读、管理后台暴露公网、TLS 套件过旧等。

**常见防护：** 配置基线与扫描、关闭调试与默认账号、最小公网暴露、云资源 ACL 定期检查、自动化合规检测。

### 20、业务逻辑漏洞

严格说不一定是「漏洞组件」，但危害很大：如优惠券可重复领、支付金额前端可改、验证码可绕过、短信轰炸、秒杀超卖、找回密码逻辑缺陷等。

**常见防护：** 金额/库存以服务端为准；关键流程做状态机校验；接口限流与风控；代码评审关注「谁能调用、能调用几次、参数能否被篡改」。

## Cookie、Token 与安全响应头

### Cookie 关键属性

| 属性 | 作用 |
| --- | --- |
| `HttpOnly` | JS 无法读取，降低 XSS 偷会话风险 |
| `Secure` | 仅 HTTPS 发送 |
| `SameSite=Lax/Strict` | 限制跨站携带，缓解 CSRF |
| `Path` / `Domain` | 控制作用范围，避免过宽 |

### Token 存放位置（前端常见讨论）

| 方式 | 优点 | 风险 |
| --- | --- | --- |
| **内存** | XSS 难持久窃取 | 刷新丢失，需 Silent Refresh |
| **HttpOnly Cookie** | JS 读不到 | 需防 CSRF |
| **localStorage** | 使用简单 | XSS 可直接读走 |

实践中常见组合：**短效 Access Token（内存）+ Refresh Token（HttpOnly Cookie）**，并配合 CSRF 防护。

### 常用安全响应头

| 响应头 | 作用 |
| --- | --- |
| `Content-Security-Policy` | 限制脚本来源，强力缓解 XSS |
| `Strict-Transport-Security` | 强制 HTTPS（HSTS） |
| `X-Content-Type-Options: nosniff` | 防 MIME 嗅探 |
| `X-Frame-Options` / `frame-ancestors` | 防点击劫持 |
| `Referrer-Policy` | 控制 Referer 泄露 |
| `Permissions-Policy` | 限制摄像头、地理等浏览器能力 |

## Web 前端 / 全栈优先关注

对前端与 Node 全栈而言，建议按优先级排查：

1. **XSS**、**CSRF**
2. **鉴权与越权**（每个写接口都要问：谁、对哪条资源）
3. **Token / Cookie 存储与传输**
4. **HTTPS、混合内容、CORS**
5. **敏感字段与密钥不进前端包**
6. **第三方脚本 / CDN（SRI）与依赖漏洞**
7. **开放重定向、点击劫持、上传与富文本**

## 纵深防御清单（实战自检）

开发与上线前可按表自检：

| 类别 | 检查项 |
| --- | --- |
| **输入** | 所有外部输入不可信；参数化；白名单优先生效 |
| **输出** | 按上下文编码；富文本消毒 |
| **认证** | MFA；防爆破；安全存密 |
| **授权** | 服务端校验；防 IDOR |
| **会话** | HttpOnly + Secure + SameSite；短过期 |
| **传输** | 全站 HTTPS + HSTS |
| **配置** | 关调试；默认口令；CORS 白名单 |
| **依赖** | 锁定版本；定期扫描升级 |
| **日志** | 记安全事件；脱敏；可追溯 |
| **应急** | 密钥可轮换；漏洞有响应流程 |

## 快速对照表

| 问题 | 主要威胁 | 一句话对策 |
| --- | --- | --- |
| XSS | 脚本执行、会话被盗 | 转义 + CSP + HttpOnly |
| CSRF | 借用户身份发请求 | Token + SameSite |
| SQL / 命令注入 | 库或主机被控 | 参数化 / 勿拼 shell |
| MITM | 窃听篡改 | HTTPS + 校验证书 |
| DDoS | 服务不可用 | CDN / 限流 / 高防 |
| 弱口令 / 撞库 | 账号失陷 | MFA + 限流 + 强哈希 |
| 越权 / IDOR | 他人数据被操作 | 服务端鉴权 + 归属校验 |
| 文件上传 | 服务器被控 / XSS | 白名单 + 隔离存储 |
| 信息泄露 | 密钥与隐私外泄 | 脱敏 + 密钥管理 |
| 开放重定向 | 钓鱼跳转 | 跳转白名单 |
| SSRF | 打内网 / 云元数据 | URL 白名单 + 出网限制 |
| XXE | 读文件 / SSRF | 禁外部实体 |
| CORS 误配 | 跨站读敏感数据 | 精确 Origin 白名单 |
| JWT / Session 误用 | 身份伪造 | 校验算法与过期、轮换会话 |
| 点击劫持 | 诱骗点击 | frame-ancestors / XFO |
| 供应链 | 依赖被污染 | 扫描 + 锁定 + SRI |
| 配置错误 | 默认敞口 | 基线加固 + 扫描 |
| 业务逻辑洞 | 资损 / 滥用 | 服务端校验 + 风控限流 |
